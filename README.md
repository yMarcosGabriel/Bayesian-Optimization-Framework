# Data and simulation outputs

## What should be archived?

The preferred archival unit is the **versioned source code plus the non-proprietary data needed to substantiate the paper's tables and figures**.

The original HFSS `.aedt` project and raw HFSS export files are intentionally excluded because their redistribution is subject to Ansys licensing terms.

### Potentially shareable derived data

If your Ansys license/institutional policy explicitly permits redistribution of derived simulation results, the following files generated by the pipeline are the most useful:

- `resultados_bo.csv`
- `tabela_resultado_final.csv`
- `resumo_grade_er_frequencia.csv`
- `historico_remodelagem_bounds.csv`
- `historico_adaptativo.csv`
- final S11/Z11 curves used directly in the manuscript

Before placing any of these in a public Zenodo record, confirm that the applicable license permits redistribution of the corresponding simulation-derived values. If it does not, **do not upload them merely because they are CSV files**.

## What can be safely included now?

This repository includes:

- the cleaned optimization code;
- the cleaned notebook;
- configuration and dependency information;
- documentation of the generated data products;
- no `.aedt` project;
- no HFSS raw exports;
- no personal filesystem paths or execution logs.

## Recommended Zenodo strategy

If the simulation-derived data cannot legally be redistributed, create a **software DOI** for the GitHub release and use the repository/Zenodo record to document the computational method. In the manuscript's Data Availability statement, explain that the HFSS project and raw simulation data cannot be publicly distributed because of licensing restrictions, while the optimization source code is openly available.

If later you obtain permission to redistribute the derived numerical data, create a separate Zenodo dataset record and link it to the software DOI.
